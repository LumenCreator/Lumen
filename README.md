# Lumen Terminal

A single-page situation terminal for geopolitical, macro and market work: a world map that
reacts to the news wire, a contagion engine that turns a shock into a ranked list of winners
and losers, link analysis between any two entities, a fair-value-gap backtest lab, large-holder
flow tracking, and a paper book with scenario risk.

No build step. Open `index.html`, or drop the folder on Netlify.

---

## Running it

**Locally** — open `index.html` directly, or serve the folder if you prefer:

```bash
python3 -m http.server 8899     # then http://127.0.0.1:8899
```

**On Netlify** — connect the repo (or drag the folder into the Netlify UI). `netlify.toml`
publishes the root and builds the one function in `netlify/functions/`. No build command.

## Demo mode vs live mode

It ships in **DEMO** mode. Everything — every headline, price, wallet, transfer and filing — is
generated by a deterministic engine in `assets/js/data/`. Simulated stories carry a `SIM` badge
and the backtest lab prints a warning above every result.

This is not a placeholder to be quietly tolerated: it exists so the analytics are usable before
you have a single API key, and so the map, cascade engine and price series describe *one
consistent world* — displacement in the price series really does cluster on the days the
generated calendar has events on, which is what makes the "when do gaps happen" analysis
demonstrable. It is not real reporting and a backtest run on it is not evidence of an edge.

Switch to **LIVE** in Settings (⚙) after adding keys. Providers:

| Provider | Gives you | Key | Callable from the browser? |
|---|---|---|---|
| Finnhub | quotes, candles, company news | yes | **yes** — works with no proxy |
| GDELT 2.0 | global event stream with country tags | no | **yes** |
| Alpaca (paper) | paper trading, positions, orders, bars | yes | no — needs the proxy |
| Marketaux | entity-tagged financial news | yes | no — needs the proxy |
| Etherscan | wallet balances and transfers | yes | no — needs the proxy |
| FMP | 13F holdings, insider trades | yes | no — needs the proxy |

### Why the proxy exists

Alpaca, Marketaux, Etherscan and FMP send no CORS headers. A browser cannot call them, no
matter how valid your key is — this is a property of those APIs, not something the page can work
around. `netlify/functions/proxy.js` is the server side that can.

1. Deploy the site to Netlify.
2. Set the keys as **environment variables** on the site (Site settings → Environment variables):
   `ALPACA_KEY`, `ALPACA_SECRET` (use *paper* keys), `MARKETAUX_TOKEN`, `ETHERSCAN_KEY`,
   `FMP_KEY`, `FINNHUB_KEY`. Optionally set `LUMEN_ALLOWED_ORIGIN` to your site's origin.
3. In the app: Settings → Proxy → `/.netlify/functions/proxy`.

The proxy only reaches an allowlist of providers and, per provider, an allowlist of paths. It
injects credentials from the deploy's environment and strips any the caller tried to send, so a
key never reaches the page. Keys you type into Settings instead stay in that browser's
`localStorage` and are only used for the two providers that can be called directly.

## The command bar

Press `/` or `⌘K`. It takes terse commands and rough english.

```

scan hormuz                    everything most tightly wired to one entity

exhaustion nvda                is this level late in its own range?

alerts                         alert rules and history

what if iran closes hormuz     free text matched to the nearest scenario seed

help                           the full list
```

## The eight views

**Desk** — the world map (Robinson projection over Natural Earth outlines), coloured by where
the wire is concentrated, pinned with high-impact events and chokepoints, with arcs joining
countries that appear in the same story. Click a country and the wire, the brief and the map all
focus on it. The wire carries macro only: trade, capital flows, energy, policy, conflict,
supply chains. Local crime and civic news is filtered out by design.

**Signals** — the behaviour layer, and the one place where being precise about limits matters
most. Four things:

*Exhaustion* answers the "who is left to buy" question directly. Given where price sits in its
own distribution and how long it has been stretched, it pulls every historical instance from a
comparable percentile and reports what actually happened next — hit rate, median, the gain when
right against the loss when wrong, and critically the **unconditional** rate beside it. Oil at
the 95th percentile of its range, extended 23 bars, showing that from comparable levels price
was lower 58% of the time over the next ten bars against a 55% base rate, is a −13 point edge on
71 overlapping windows: real, small, and worth sizing down into rather than up on. That framing
is the whole point — a level with no edge over the base rate is told to you plainly rather than
dressed up.

*Anomalies* flags bar patterns consistent with liquidity sweeps, climax distribution, churn,
unexplained volume, absorbed catalysts and gap-fades, plus round-number pinning across the
series.

*Event studies* is the honest version of "after X happens, people buy". Pick a catalyst class —
oil shock, conflict escalation, hawkish surprise, tariff action, chokepoint threat — and it
measures what the instrument actually did after every instance in the window, against its
unconditional behaviour, with n and a t-statistic shown. Most of the time the answer is "no
measurable reaction", and it says so.

*Alerts* turns any of the above into a rule that fires before a level rather than at it. Rules
run whenever the world refreshes and every few minutes while the tab is open, with per-rule
cooldowns. Browser notifications are opt-in.

**A hard limit worth stating up front:** OHLCV bars carry no order book, no cancellations and no
counterparty identity. Spoofing, layering, wash trading and marking the close are defined by
*intent* and by order-level behaviour that is simply not in this data. Everything in the anomaly
scanner flags a *pattern consistent with* those behaviours, and most of those patterns also
occur for entirely ordinary reasons — an index rebalance, a large hedger, a scheduled roll.
Treat every flag as "look at this", never "this happened". Genuine market surveillance needs
full order-book and participant data that no retail API sells. The app says this in the view
itself, not just here.

**Main Street** — the household layer. A cost-of-living basket (mortgage, energy, fuel,
groceries, insurance, repairs, health, telco, vehicle, discretionary) ranked by how hard each
line is squeezing right now, each with the listed companies on the receiving end and the ones
paying for it.

Alongside it, disaster response playbooks. A catastrophe is not one trade, it is a sequence:
emergency response, then claims, then materials, then vehicles, then infrastructure — each phase
with different companies and a different window. Five hazard types (flood, cyclone, bushfire,
earthquake/tsunami, drought) across Australian and US listings, with a timeline slider: move it
and the generated stock list reorders, because the trade in week one is not the trade in month
nine. The Australian chain is covered in depth because it is unusually concentrated — roof tiles
run through one listed name, catastrophe restoration through another.

**Cascade** — pick a shock, set severity, and the engine propagates it through a causal graph of
~60 nodes and ~130 edges. Every edge carries a conditional probability, a lag in days, a
magnitude and the mechanism in plain english, so the output is an auditable chain rather than a
score. It produces: the narrative chain, the transmission graph, ranked beneficiary and casualty
industries, net macro factor pressure, instrument-level expressions, and a second-order panel
answering "if this one absorbs the hit, where does the pressure go next".

The worked example from the original brief runs end to end:
*Middle East escalation → Hormuz transit disrupted → crude and LNG spike → wholesale power
prices → household electricity bills → cost-of-living squeeze → discretionary spending contracts
→ public anger → incumbent under threat → subsidies → deficit → bond supply → rates higher* —
with defence, energy, mining and batteries ranked as beneficiaries and airlines, retail, autos
and software as casualties.

**Backtest Lab** — fair value gap detection (three-candle displacement gaps), full statistics
(count, per-session rate, size distribution, mitigation rate at touch / 50% / full fill, time to
fill), and the "when do they show up" analysis: by weekday, by hour, as a daily calendar
heatmap, and event-days versus quiet days. On top of that sits a configurable strategy —
entry at the zone, stop beyond the far edge, R-multiple target — with an equity curve, expectancy,
profit factor, drawdown, a trade blotter and a one-parameter-at-a-time sweep so a curve fit is
visible as one.

It also runs **anchored periodic backtests**: restart the strategy at the beginning of every
day, week, month, quarter or year with the same capital and an empty book, so no period inherits
the one before it. Each period is measured against simply buying at the period open and holding.
This is what makes a lucky run visible — a single continuous equity curve hides the fact that
all the profit came from one quarter, and the panel reports exactly what share of the total came
from the best single period. Above 60% and it tells you plainly that you are looking at one good
run wearing a costume.

**On TradingView**: TradingView has no public API for running backtests, so nothing here can
drive it remotely — any tool claiming otherwise is scraping. What this does instead is
reimplement the strategy locally and accept TradingView's own **chart CSV export** ("Export chart
data" on any chart). Import it and the entire lab runs against your real bars instead of the
demo series. That is the honest bridge, and it is the only one that exists.

**Link Analysis** — `link tsla to crudeoil` answers the question three independent ways:
*mechanism* (k-best paths through a structural graph of ownership, sector membership, factor
exposure, geography, chokepoints, trade and causal edges), *statistics* (rolling correlation,
beta, and a lead/lag profile), and *narrative* (co-occurrence in the wire, with deals, trades
and policy items called out separately). The verdict reports how many of the three agree,
because that is the part that matters: mechanism without correlation is a dormant link,
correlation without mechanism is usually shared market beta and will break when the regime does.

**Flows** — large-holder tracking. On-chain: a transfer ledger across chains, net exchange
flow read as accumulation or distribution, and a ranked accumulating/distributing list.
Institutional: 13F-style position changes and insider activity aggregated by industry.

**Book & Risk** — a local paper book (browser-only, nothing leaves the page), position sizing
from your risk settings, exposure by industry and country, concentration warnings, parametric
VaR, what each scenario does to the book with hedge suggestions, and a probability × impact
matrix across every scenario. Connect Alpaca and a paper account panel appears alongside it with
positions, open orders and an order ticket.


Plain classic scripts on purpose — no bundler, no ES modules — so `index.html` works when
opened straight off disk.

## Honest limits

- **The demo world is not real.** It is internally consistent and useful for learning the tools.
  It is not evidence about markets.
- **Cascade probabilities are assumptions.** They are the edge weights written into
  `cascade.js`, informed by how these transmissions have historically worked, not measured
  frequencies. Read them as a structured argument, and change them if you disagree — they are
  in one table.
- **Backtest results carry no costs.** No slippage, no commission, no borrow. Subtract roughly
  0.05–0.15R per trade before believing anything.
- **VaR is parametric** with a flat correlation assumption. It understates the tail, which is
  precisely why the scenario panel exists next to it.
- **13F data is filed up to 45 days late.** It tells you where money went, not where it is going.
- **Exchange flow is a heuristic.** An inflow can equally be a market maker rebalancing.
- **The anomaly scanner cannot detect manipulation**, only patterns consistent with it. See the
  Signals section above — this is the most important limit in the app.
- **Conditional base rates use overlapping windows** from a single price path. Fifty windows are
  not fifty independent observations, so every t-statistic here overstates its confidence. The
  app reports n everywhere so you can see when a number is too thin to lean on.
- **Disaster buy lists are a research starting point, not a portfolio.** The chain says who is
  structurally exposed to a rebuild; it says nothing about whether that exposure is already in
  the price, which after a widely reported catastrophe it usually partly is.
- **Household budget shares are approximations** of the shape of expenditure surveys, not a
  specific ABS/ONS/BLS release. They order the categories sensibly; do not quote them.
- **Alerts only run while the tab is open.** There is no server. Overnight alerting would need
  the check to run somewhere that stays up.
- **Nothing here is investment advice.** Trading goes to Alpaca *paper* accounts. Do not point
  this at a live brokerage without reading the order path in `providers.js` yourself.
